# Поток — рабочий прототип интерфейса

Файл: **`index.html`** — один самодостаточный файл (HTML + CSS + JS). Открывается двойным кликом в любом браузере, интернет и сборка не нужны.

Это не картинка и не «кликабельный макет»: внутри работающее приложение с mock-бэкендом, который реализует REST-контракты из ревью ТЗ — с реальными кодами ответов (401/403/404/409/422/428/429), задержками, телом ошибки в формате RFC 7807 и журналом вызовов.

---

## Как смотреть

1. Откройте `index.html`.
2. Нажмите любой из трёх демо-аккаунтов на экране входа (пароль подставляется сам):
   - **Иван Иванов** — владелец, доступно всё;
   - **Пётр Петров** — менеджер: сравните, как меняется интерфейс и права (нет приглашений и экспорта);
   - **Дмитрий Соколов** — приглашённый сотрудник: покажет живую ошибку 403.
3. Пункт меню **«Демо-стенд»** — главный экран для проверки: напишите сообщение «от клиента» в макет Telegram и посмотрите, как обращение проходит вебхук, очередь, AI-разбор, создание задачи и push менеджеру.

Быстрые клавиши: `⌘K` / `/` — палитра, `N` — новая задача, `B` / `T` — доска / таблица, `?` — подсказка, `Esc` — закрыть.

---

## Что специально можно «сломать» (Демо-стенд → Аварийные режимы)

| Режим | Что показывает |
|---|---|
| AI-провайдер недоступен | Обращение не теряется: задача создаётся с исходным текстом, анализ уходит в ретрай |
| Другой менеджер забрал задачу раньше | Второй клик «Взять в работу» получает честный 409 с объяснением, карточка не «залипает» |
| Telegram отвечает 429 | Уведомление уходит в очередь с retry_after, задача на доске уже есть |
| Менеджер офлайн | Правки копятся в очереди и синхронизируются при восстановлении сети |
| Клиент пишет три сообщения подряд | Сообщения склеиваются в одну задачу (окно 90 секунд) — нет дублей |

Плюс в демо-боте есть кнопки «Клиент заблокировал бота» (403 от Telegram) и «Вложение».

## Что есть в интерфейсе

- **Канбан-доска**: 4 колонки, drag-and-drop с optimistic update, откат при конфликте версий, контекстное меню карточки (работает и на телефоне, где DnD неудобен), SLA-таймеры и просрочки.
- **Карточка задачи**: исходное сообщение клиента + уверенность AI, переписка, описание с AI-дополнением, ответ клиенту в Telegram с AI-черновиком, комментарии, история изменений (кто, что, когда).
- **Клиенты**: привязка к организации, история переписки, предупреждение «заблокировал бота», ответ из карточки.
- **Сотрудники**: роли, статус приглашения, привязка Telegram, загрузка; отключение сотрудника возвращает его задачи в общий пул.
- **Аналитика**: SLA, первый отклик, воронка, категории, нагрузка менеджеров, качество и стоимость AI.
- **Настройки**: организация, категории, шаблоны автоответов, SLA по приоритетам, Telegram-бот, матрица прав, активные сессии, журнал аудита, 152-ФЗ.
- **«Как устроено»**: 12 изменений относительно исходного ТЗ (было → стало) + конвейер, машина состояний, список эндпойнтов и таблица НФТ.
- **Журнал API**: каждая строка раскрывается в request/response. Это не декорация — интерфейс действительно ходит в mock-бэкенд.

Тёмная тема, адаптив до 390 px, работа с клавиатуры, состояния загрузки и пустые состояния.

## Чего здесь нет (честно)

- Настоящего бэкенда и БД: данные живут в браузере, при перезагрузке демо-сценарии сбрасываются.
- Настоящего Telegram-бота: переписка эмулируется, чтобы сценарий был воспроизводимым.
- Настоящей LLM: категория и приоритет определяются правилами с видом «как AI».
- Продакшен-безопасности: токены демонстрационные, RLS, шифрование и подписи — требования из ревью, а не код.

Для отладки в консоли браузера доступен `window.__POTOK` (db, state, scenario, Api, bus).

## Как это связано с ревью ТЗ

Каждый пункт из `Ревью_ТЗ.md` либо виден в интерфейсе, либо воспроизводится на демо-стенде:

| Пункт ревью | Где посмотреть |
|---|---|
| Мультитенантность (clients + organization_id) | Клиенты, Настройки → Организация, «Как устроено» |
| Асинхронный конвейер вместо синхронного AI | Демо-стенд → «Конвейер обработки» |
| Идемпотентность вебхука | Журнал API → `Idempotency-Key`; повторный POST возвращает тот же результат |
| История переписки (таблица messages) | Карточка задачи, карточка клиента |
| Гонка при взятии задачи | Аварийный режим «Другой менеджер забрал задачу раньше» + version/If-Match |
| Auth, refresh, отзыв сессий | Вход, Профиль и безопасность, Настройки → Безопасность |
| Права и 403 | Войдите менеджером: экспорт и приглашения вернут отказ |
| SLA, приоритеты, эскалация | Доска, Аналитика, Настройки → SLA |
| Аудит действий | Настройки → Аудит |
| 152-ФЗ и AI | Настройки → Безопасность, «Как устроено» |
| НФТ и приёмка | «Как устроено» → таблица НФТ + аварийные режимы как приёмочные сценарии |
